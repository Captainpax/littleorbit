# Security policy

## Reporting a vulnerability

Do not publish an issue containing an exploitable vulnerability, credential, personal data, or production detail. Contact the repository owner privately through the security advisory feature on GitHub. Include affected versions, reproduction steps, impact, and any suggested mitigation. Please allow time to investigate before public disclosure.

## Supported versions

Until 1.0, only the current default branch receives security fixes. After 1.0, the latest minor release will be supported unless a release note says otherwise.

## Security boundaries

The public gateway is the only exposed container port. Authentication does not imply authorization to a couple resource. AI is isolated from answers and relationship data. Big Orbit views exclude relationship content, attachment names and bytes, quiz answers, precise locations, and profile images. Tokens, Big Orbit device credentials, and recovery codes are stored only as hashes; TOTP secrets, Android Keystore administrator keys, Android profile thumbnails, queued Smooches, kept-offline note attachments, and the phone's reusable wireless-ADB private key stay in protected or app-private storage. Smooch creation is transactionally rate-limited to five sends per account in a rolling hour, and account deletion erases the old relationship history. Server relationship avatars are normalized to bounded metadata-free WebP variants and are available only to the active couple. Precise coordinates are scheduled for deletion five minutes early and have a separate absolute 24-hour purge predicate.

Privileged `/v2/admin` sessions require an administrator password, current replay-safe MFA proof, and possession of an explicitly enrolled P-256 Android Keystore key. Five-minute challenges are single-use, 30-minute sessions are bound to one device record, 90-day device credentials are random and hashed, and revocation invalidates that device without disclosing whether unrelated protected records exist. `/v1/admin` and the browser `/admin` interface are absent after cutover. Typed operation jobs cannot contain commands, SQL, paths, URLs, or arbitrary parameters.

Quiz feedback is accepted only for a launch-forward global question after shared reveal. Authorization precedes quiz-day/question lookup, operation IDs make retries idempotent, and optimistic revisions prevent silent overwrite. Linked feedback is author-readable for 30 days, then unlinked; raw optional review text is deleted by 90 days. Review text must have separate consent and pass bounded rejection of contact details, URLs, control characters, and instruction-shaped input. Admin and learning views require at least five distinct contributing accounts and omit account, couple, quiz-day, and answer identity.

The public-context fetcher owns no application secret or private-network route. It accepts only exact code-owned HTTPS sources, resolves only public addresses, refuses redirects, bounds MIME type and response size, removes active markup, and passes instruction-shaped text through a fail-closed sanitizer. The worker cannot request an arbitrary URL.

Together-time collection health is a separate, opt-in, latest-only diagnostic
record. It contains bounded device and collection state without coordinates,
network identifiers, or an installation identifier in partner responses. Only
the active partner can read an opted-in snapshot. Opt-out, unpairing, or 24-hour
expiry removes it. Administration and notification paths never expose it, and
coordinated database backups exclude its table alongside raw coordinates.

Login, verification resend, password recovery, reset, pair redemption, and administrator proof routes use PostgreSQL-backed fixed-window limits. The service hashes IP addresses, normalized emails, reset tokens, or account IDs with a scope-specific keyed digest before persistence, applies the IP bucket before attacker-controlled subjects, caps each counter, and removes inactive buckets after 24 hours. Counters commit outside the protected application transaction so an invalid request or rollback cannot erase the attempt.

FastAPI accepts the gateway's single-address client header only when the socket peer matches the configured immediate proxy. Invalid, comma-separated, or untrusted values fall back to the direct peer. Production must configure that value for the immediate gateway-to-API hop and verify it after container recreation; the upstream Nginx Proxy Manager address is not the API's direct peer when Caddy sits between them. Registration always performs Argon2id work and uses an atomic conflict-safe insert. Verification resend and password recovery also perform the same dominant password work for known and unknown addresses, then serialize token creation under the account lock with a five-minute cooldown.

A password reset locks the account, consumes every outstanding reset link, replaces the Argon2id password hash, and revokes all sessions atomically. Login rejects deleted, suspended, or unverified accounts. Session issuance, rotation, bulk revocation, and account deletion share the account row as their outer lock, preventing an old credential from racing a reset into a surviving session.

Replacing enabled administrator MFA requires the current password and either a current replay-safe TOTP or an unused recovery code. The replacement secret is encrypted in a bounded pending challenge while the current factor remains active. Confirmation rechecks the account and calling session, swaps the factor, stores only new recovery-code hashes, revokes every previous session, and returns one new MFA session. The configuration endpoint builds an explicit operational allowlist and never serializes the settings object or secret-bearing connection strings.

Pairing transitions lock both account rows in stable UUID order and recheck verification, suspension, deletion, active membership, code expiry, and creator confirmation inside the transaction. Unpairing and deletion use the same lock order and immediately remove ephemeral relationship state. Legacy quiz answers appear in exports and former-pair archives only for questions answered by both original participants.

Note attachments require current couple authorization before note or file lookup. Server-generated storage keys prevent path selection, request streams and chunks are bounded, exact offsets prevent gaps and overwrite races, and an operation ID can resume only the same declared bytes. Unscanned content is never downloadable. ClamAV runs on an internal-only network and scanner outages fail closed; images, PDFs, audio, and video are re-encoded or remuxed without source metadata before availability. The Android client verifies the sanitized SHA-256 digest before previewing or retaining an offline copy. File deletion and expired-note cleanup remove private volume bytes.

An explicit offline-conflict fork locks and reauthorizes the active couple,
accepts only clean attachments owned by the source note, reserves quota before
copying, verifies every copied digest, and rewrites all attachment references.
Missing or foreign mappings fail closed. Automated duplicate archival is
limited to exact, untouched, attachment-free copies and requires a verified
encrypted backup manifest before applying any change. Ambiguous groups remain
untouched and archived notes retain the normal seven-day recovery window.

Partner notification endpoints authenticate the account before installation or event lookup. Installations use random app-generated UUIDs, and event delivery is scoped to one installation. Little Orbit does not use Firebase, another hosted push broker, or provider-issued device addresses. A visible app receives a content-free `notification.available` hint through the authenticated first-party WebSocket; background WorkManager jobs poll the same self-hosted API and may be delayed by Android power management. The client fetches current authorized metadata before display and acknowledges only after Android accepts the post. A legacy account-wide Smooch acknowledgement cannot consume modern per-installation delivery. Public lock-screen versions remain generic. A note alert never contains its body or attachment metadata, repeated edit alerts are cooled down, and active partner presence suppresses the alert.

Note and notification WebSockets retain only a session digest and account identifier. They revalidate the exact session and active account after hub registration, before every client operation, and every 30 seconds while idle. Note mutations repeat the check inside their transaction before locking relationship content. Revocation, expiry, suspension, deletion, unpairing, or disabling a notification installation closes the affected socket rather than letting its initial authentication live indefinitely.

After authentication, every active-couple path returns the same structured `relationship_inactive` 409 when membership or the couple disappeared or ended. Android treats only that exact code as permission to purge local relationship caches; old-archive failures and ordinary edit/revision conflicts keep distinct errors.

An HTTP 401 from an authenticated Android repository, background display refresh, or profile refresh is terminal session loss. Android clears the encrypted token, account and relationship caches, drafts, retained media, notifications, and private background work before rendering signed out. Public login failures and a wrong password entered as deletion proof do not erase an otherwise valid local session. This separation prevents cached avatars from making a revoked or expired account look half-paired while retaining the relationship-only meaning of `relationship_inactive`.

## RC14 server acceptance gate

Before a 1.0 release, verify the migration on a disposable PostgreSQL database and exercise limit expiry/capping, neutral recovery responses, concurrent reset links, reset-versus-session rotation, deleted-account login, TOTP replay, recovery-code reuse, staged MFA replacement, old-session revocation, configuration allowlisting, pair-code expiry/reuse/races, one-sided legacy quiz exports, WebSocket revocation while active and idle, independent multi-install notification acknowledgements, legacy Smooch migration, concurrent delivery backfill, strict rejection of retired hosted addresses, category disablement, and unpair purge. For together-time, verify exact relationship scoping, duplicate versus conflicting sample IDs, concurrent member uploads, consent and relationship loss, correction preservation, restart durability, and the absolute raw-coordinate retention ceiling. Verify that the APK dependency graph, server dependencies, container environment, and runtime network flow contain no hosted notification provider. Never run the destructive isolated integration suite against production data. Setting `LITTLE_ORBIT_TEST_DATABASE_URL` makes the test harness select that exact URL as `DATABASE_URL`; leave it unset outside a disposable database.

The in-app Wear installer accepts APK metadata only from the exact first-party versioned HTTPS route and verifies byte count, SHA-256, package name, version code, required watch feature, and the pinned signing certificate. It associates DNS-SD results with the discovered host and network, removes lost services, refreshes the post-pair connection port, and retries only bounded TLS transitions. Visible manual endpoints remain authoritative until the person restarts discovery. It proves authorization with a harmless ADB command before reading privacy-safe compatibility properties. It blocks phones and downgrades. Pairing uses bundled public Conscrypt APIs; hidden-API bypass code is excluded. The code field disables saved state and autofill, clears before work continues and when the screen stops, and request diagnostics redact it. Safe diagnostic codes never retain pairing codes, endpoints, fingerprints, or raw transport errors. A watch security patch older than May 1, 2026, or an unreadable patch level produces a warning that requires an explicit choice before installation. Wireless debugging should be disabled on the watch after setup.

Passive Android display records include an opaque relationship fingerprint and monotonic local generation, never a token or server account/couple identifier. Sign-out, unpairing, deletion, and inactive-relationship responses advance an urgent durable purge. Wear applies purge records first, rejects delayed older generations and legacy records after migration, and rechecks asset authorization before file replacement. If no phone delivery arrives, it marks the cache stale after six hours and deletes relationship display values, names, thumbnails, and partial files after 24 hours. An alarm, reboot receiver, and every passive read enforce the same boundary.

Automatic update work retrieves signed release metadata only. It never downloads APK bytes or opens Android's installer without a person's explicit action. Required compatibility floors may bypass the optional check preference, but every candidate still passes origin, byte-count, checksum, package, version, and signer validation.

Relationship avatars are keyed to the active couple and subject account. Only the other current member may mutate one, self-assignment is rejected by both service logic and a database constraint, and unpairing deletes both images. The RC13 migration deliberately clears older account-owned photos rather than changing their ownership meaning silently.

Countdown reminder offsets are account-private even though the countdown is shared. Partner alerts exclude countdown notes and reminder choices; quiz alerts identify only a UTC date. Daily quiz-alert preparation uses a nested transaction so its failure cannot roll back or suppress unrelated Smooch, note, or countdown deliveries. Calendar export is an explicit one-way Android intent and grants Little Orbit no calendar-account credential or read access.

Never use development keys or Mailpit in a public deployment. Follow the deployment and backup runbooks and verify restore behavior before serving real users.
