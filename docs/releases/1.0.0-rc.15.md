# Little Orbit 1.0.0-rc.15

## Published prerelease

RC15 is the current signed release candidate. Phone and Wear downloads are hosted by the Little Orbit API with resumable byte ranges and mirrored in the matching GitHub prerelease. It remains a test release while the complete physical-device and external-service gates stay open.

## What changed

- Removed Firebase Messaging and every other hosted notification transport from Android, the API, the worker, dependencies, secrets, and Compose configuration.
- Kept partner alerts fully self-hosted: a visible Android app receives an authenticated, content-free WebSocket hint and fetches authorized event metadata from Little Orbit; background WorkManager checks the same HTTPS API.
- Added an RC14 compatibility boundary that accepts only `push_token: null`, rejects any provider address, and always reports the self-hosted transport.
- Deleted seven retired provider-address and delivery-attempt database fields plus their partial index while preserving random installations, notification choices, pending events, independent acknowledgements, and alert history rules.
- Deleted retired Android provider-token preferences during upgrade. Notification permission, channel state, account choice, and relationship authorization still gate every local post.
- Retained the RC14 responsive shell, shared-note discovery repair, attachment hardening, relationship purge behavior, and other feature work.

Background alerts are eventual rather than instant when the app is not visible. Android Doze and manufacturer battery rules can delay the nominal 15-minute polling interval.

## Verified so far

Repository-wide Python tests, Ruff, strict mypy, Android unit tests, phone and Wear lint, API 36 instrumentation, and a disposable PostgreSQL migration/integration gate pass. The exact signed RC14 phone APK upgrades in place to the signed RC15 candidate on API 36 and cold-launches without a fatal error. The same signed replacement succeeds on the authorized physical Pixel and remains running after a cold launch. A fresh disposable pair also passes partner document discovery, bidirectional live edits, reconnect convergence, first-party WebSocket hints, and independent installation acknowledgement. The dependency tree and merged manifest contain no Firebase Messaging integration, and the APK contains no messaging service, messaging event receiver, or FCM endpoint.

Promotion to 1.0 still requires the complete physical two-phone, tablet, widget, Pixel Watch, external SMTP, TLS renewal/recovery, and administrator MFA gates.
