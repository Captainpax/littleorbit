# Little Orbit 1.3.0 implementation candidate

Status: source-complete candidate; not yet signed or published

Little Orbit and Big Orbit now share the `1.3.0` release-train label. The intended immutable identities are Little Orbit phone code 29, Wear code 21, and Big Orbit code 3. These codes describe the current source configuration only until exact signed artifacts are built, inspected, device-tested, and published. A failed signed candidate will be discarded without reusing its code or bytes.

## Highlights

- Saturday 09:00 `America/Los_Angeles` learning and theme planning, followed by Sunday 09:00 generation for the next Monday-through-Sunday week.
- One weekly arc, seven distinct daily themes, at most two inclusive observance-centered days, and an exact daily mix of three themed plus two variety questions across one light, two reflective, and two deeper prompts.
- Reviewed Markdown retrieval through manifest-verified chunks and pgvector, bounded allowlisted public context with a 30-day sanitized fallback, and deterministic learned-policy evaluation. No model weight training and no relationship data enter the AI boundary.
- A one-use reserve of 1,825 general and 365 consent-centered intimacy questions, plus same-day, same-week, and 365-day semantic duplicate rejection for global content.
- `/v4/quizzes` responses expose public theme, depth, role, and tag metadata while retaining the existing private-until-reveal answer and author-private feedback rules.
- Big Orbit observability for schedule, knowledge, context freshness, reserve capacity, weekly plans, and generation runs, plus a fixed typed regenerate-next-week operation and content-free degraded-state alerts.
- Terminal-issued eight-digit Big Orbit bootstrap PINs with ten-minute expiry, five-attempt lockout, one-active-setup invalidation, resumable restricted setup, P-256 key proof, and first-owner TOTP QR enrollment.
- Small Ubuntu-only CI workflows with cancellation, timeouts, dependency caches, static checks, unit tests, debug builds, lint, and artifact-isolation checks; CI does not start PostgreSQL, Ollama, Android emulators, signing, or production deployment.

## Compatibility and migrations

- Database head advances from 0029 through 0030 (themes, retrieval, reserve, and learning cursor) and 0031 (Big Orbit bootstrap state).
- Phone compatibility floor remains code 23 and no forced-update deadline is introduced.
- The quiz v4 route is additive. Existing v2/v3 behavior remains available for supported clients.
- Release builds must contain no smoke endpoint, QA label, QA signing metadata, or bundled smoke APK.

## Open release gates

The candidate still needs exact signed Little Orbit and Big Orbit artifacts, release-manifest/APK verification, physical phone and Wear upgrade observation, Big Orbit fresh-device and returning-device enrollment QA, the two-partner privacy/accessibility matrix, production migration/backup evidence, and immutable publication. Until those steps are recorded, 1.2.0 and Big Orbit 1.0.0 remain the published stable releases.
