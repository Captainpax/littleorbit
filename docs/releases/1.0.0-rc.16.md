# Little Orbit 1.0.0-rc.16

## Published prerelease

RC16 is the current signed release candidate. Phone and Wear downloads are hosted by the Little Orbit API with resumable byte ranges and mirrored in the matching GitHub prerelease. It remains a test release while the complete physical-device and external-service gates stay open.

## What changed

- Fixed an expired or revoked Android session appearing as a half-paired relationship with cached partner photos, “Not connected,” and inaccessible shared notes.
- Authenticated repository, Home-display, and profile refreshes now treat HTTP 401 as terminal session loss. The phone clears its encrypted token, thumbnails, relationship cache, drafts, retained media, notifications, and private background work before rendering signed out.
- Kept public login and wrong-password deletion failures outside that purge path so a rejected credential entry cannot erase a valid session.
- Kept `relationship_inactive` separate: it clears the old relationship while preserving a valid account session for pairing again.
- Prevented a delayed Home refresh callback from restoring the misleading signed-in fallback after session cleanup.
- Hidden the Home setup checklist when pairing, notifications, mutually enabled nearby time, and the home widget are all ready. The checklist returns if one of those live requirements is later revoked, while optional watch setup remains in Settings.
- Made Pairing & relationship detect the server-owned relationship state before rendering. Active couples see a direct, confirmed **Unpair from partner** action that stops sharing, preserves both private read-only archives, disconnects live notes, and triggers phone/widget/Wear cleanup.
- Retained RC15's fully self-hosted notification transport and the exact RC14 Wear companion bytes.

The server-side pairing transaction and couple data were not changed. A person whose old session was already revoked must sign in again once; the existing active pairing and shared-note directory then remain available to that account.

## Verified so far

Android data/mobile unit tests and phone lint pass. An isolated paired API 36 account opened the shared-note directory and verified sanitized inline PNG/GIF previews. After its server sessions were revoked, a cold launch cleared the encrypted session and profile thumbnails, rendered the signed-out Home, and logged no fatal Android event. The disposable stack, accounts, attachment bytes, and volumes were removed afterward. The signed code-21 APK then upgraded the authorized physical Pixel in place, preserved its valid session, hid completed setup, and rendered the connected-only unpair control without changing the real relationship.

The self-hosted API published RC16 at `2026-09-15T05:34:32.418302Z`. Complete public phone and Wear downloads matched the signed byte counts and SHA-256 values, a 1,024-byte resumed phone request returned `206` with the exact total, the download/patch-note/RSS pages returned RC16, and all eight production services remained running without a fatal log match.

Promotion to 1.0 still requires the complete physical two-phone, tablet, widget, Pixel Watch, external SMTP, TLS renewal/recovery, and administrator MFA gates.
